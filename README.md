# 多 ETF 动量轮动 · 智能交易模拟系统

零依赖（仅 Node 内置模块）的 ETF 交易模拟与盯盘工具集。行情来自腾讯行情（前复权日K + 实时 qt），支持**多 ETF 动量轮动**（半导体设备 / 医药 / 有色），策略引擎为 50 分基准的综合评分 + 目标仓位模型，融合六大维度：

1. **技术面**（MA/MACD/RSI/KDJ/BOLL/ATR/MFI）
2. **主力资金方向**（东财主力/超大单净流入、连续流入流出天数）
3. **市场情绪面**（赚钱效应指数、涨停/跌停家数、涨跌分布）
4. **消息面**（新闻标题关键词情感打分，含时间衰减）
5. **宏观利率**（美债10Y / 中债10Y：利率上行压制高久期成长股，含 52 周新高、20 日趋势）
6. **科技板块**（费半 SOX 隔夜联动、科创50 相对沪深300 超额强度）

## 研究台账与自学习（回答"你到底准不准"）

系统会把**每一次咨询的结论**（方向、概率、关键位、依据、置信度）结构化落盘，到期后**自动拉真实行情结算**，
再用 **Hedge 在线学习**把结果回灌成专家权重与概率标定参数。

**第一次真实结算的结果（2026-09-13）**：5 条"未来1天"预测命中 1 条（20%），
归因发现是**方向标签阈值与概率不自洽**（41% 的上涨概率被标成"震荡"）。修正阈值后，
同一批样本命中率 20% → 80%。这就是台账的价值：**"震荡"看起来永远不会错，没有结算就永远发现不了这个 bug**。

**v2 扩样本后的样本外成绩单**（**47 标的 / 105,887 样本 / 640 根日K / 21 个专家**，测试集 20,915 条）：

| 周期 | 朴素基准 | 手工权重 | 学习后（样本外） | 手工→学习 |
| --- | --- | --- | --- | --- |
| 未来 1 天 | 51.6% | 49.0% | **51.3%** | +2.3pt |
| 未来 3 天 | 51.4% | 51.5% | **52.2%** | +0.7pt |
| 未来 1 周 | 50.7% | 50.2% | **52.1%** | +1.9pt |
| 未来 1 月 | 52.3% | 46.4% | **54.5%** | +8.1pt |

**含费实盘回测**（已计入 ETF 0.08% / 个股 0.18% 双边成本，阈值在验证集上按期望收益选出、测试集复核）：

| 周期 | 阈值 | 交易数 | 胜率 | 单笔期望 | 单笔夏普 |
| --- | --- | --- | --- | --- | --- |
| 未来 1 天 | 0.58 | 1320 | **53.3%** | +0.399% | 0.108 |
| 未来 3 天 | 0.56 | 167 | **68.3%** | +2.688% | 0.362 |
| 未来 1 周 | 0.66 | 186 | **66.7%** | +4.052% | 0.386 |
| 未来 1 月 | 0.50 | 2511 | **56.0%** | +4.477% | 0.230 |

**Walk-forward 滚动验证**（4 折，完全模拟"逐日向前交易"）：平均方向命中率 **52.0%**（各折 51.3% / 57.3% / 48.9% / 50.5%）。

**模型 vs 朴素动量：决胜检验（同一测试集、McNemar 配对，`node ablation.js`）**

| 任务口径 | 谁更好 | 证据 |
| --- | --- | --- |
| **时序方向**（这只标的明天涨不涨） | **模型** | 方向准确率 **54.40% vs 纯动量 50.13%**，新增对 1228 / 丢失 905，**p = 2.8×10⁻¹²（极显著）** |
| **横截面排序 · 1月**（该买哪几只） | 模型 | 胜率 57.4% vs 47.4%，期望 +3.21% vs +2.98% |
| **横截面排序 · 1周** | **动量** | 期望 +1.44% vs +0.70%（动量为模型两倍） |
| **组合净值口径（w1）** | 两期相反 | 验证集最优 w=0.25，测试集最优 w=1.00（纯动量）→ 权重不可靠估计 |

> **结论：模型不是没用，而是此前被用错了地方。** 它的显著优势在**时序方向**（单只标的该不该持有），
> 而线上 `pickRotation` 把它用在了**横截面排序**上 —— 那恰好是动量的强项。

**「动量排序 + 模型择时」检验结果**（P4，组合口径 T+1 含费，16 种组合）：

| 族 | 组合数 | 验证集胜出 | **测试集胜出** | **两期都胜出** |
| --- | --- | --- | --- | --- |
| **A 入场门槛**（模型概率 ≥0.50/0.55 才建仓） | 6 | 6/6 | **5/6** | **5/6** ✅ |
| B 择时退出（概率跌破就平仓） | 4 | 4/4 | **0/4** | **0/4** ❌ |
| C 概率定仓 | 2 | 2/2 | 1/2 | 1/2 |

w1 周期、测试集，**动量 + 入场门槛 ≥0.55**：交易 44 笔、收益 **41.58%**、最大回撤 **22.05%**、
Calmar **4.717**、胜率 54.5% —— 相对纯动量（77 笔 / 27.27% / 29.91% / 2.138）**全面更优且换手减半**。

> ⚠️ **但这只是 post-hoc 观察，不是验证集选出的结论**（验证集选出的是失败的 B 族）。
> 因此**本轮不改线上行为**，而是交给前向检验：`node ledger.js gate` 用台账已结算快照
> 对比"门槛通过 vs 不通过"的真实表现。当前有效样本量仅 1 个到期日，命令会拒绝下结论。

**消融实验**（`node ablation.js`，在**完全相同的测试集**上做配对显著性检验，7,565 条样本）：

| 配置 | 标的 | 日K | 专家 | 方向命中率 | 相对基线 | McNemar p |
| --- | --- | --- | --- | --- | --- | --- |
| A v1 基线 | 17 | 400 | 11 | 52.61% | — | — |
| B +更多标的 | 47 | 400 | 11 | 52.93% | +0.32pt | 0.462 不显著 |
| C +更长历史 | 17 | 640 | 11 | 52.65% | +0.04pt | 0.900 不显著 |
| D +更多专家 | 17 | 400 | 21 | 53.19% | +0.58pt | 0.231 不显著 |
| **E v2 全量** | 47 | 640 | 21 | **53.83%** | **+1.22pt** | **0.022 显著** |

> **结论**：扩样本**整体**有效（p=0.022），但**任何单个维度都不显著** —— 收益是叠加出来的。
> 尤其**"更长历史"几乎零贡献**（+0.04pt，p=0.90）：数据的"相关性"比"数量"更重要。
> 含费胜率的提升来自**筛选本身**（不筛选 53.01% → 阈值筛选 57.9~60.5%），**不是来自扩样本**。

> ⚠️ **诚实的边界**：
> 1. **概率的技巧分仍 ≤ 0**（Brier ≈ 0.25）—— 概率幅度本身不提供额外信息，系统已用 Platt 标定把"70%"压回可信区间。
> 2. **高阈值档位交易数少**（d3/w1 仅百余笔），胜率会偏高，必须结合"交易数"一起看。
> 3. **优势很薄且不稳定**：滚动验证中有一折低于 50%。**必须靠止损与仓位控制，而不是靠预测。**
> 4. **组合口径的换手极高**：周频 topK=3 的换手约 **5000–5900%**（≈ 每月 1000%），
>    最大回撤 **23–37%** —— 这个配置对 50 万本金**换手过高、回撤过大**，不宜按此执行。
> 5. **前视偏差已量化**：改成 T+1 开盘成交后，测试集总收益仅降 **−1.41pt**，说明历史数字基本诚实。

详细说明见 `reports/下一步落地与扩样本效果-20260913.md`、`reports/研究台账与自学习系统-诚实性说明-20260913.md` 与 `reports/Hedge学习器训练报告-20260913.md`。

## 快速开始

```bash
# 1) 启动 Web 模拟系统（可选）
node server.js            # 打开 http://127.0.0.1:8899

# 2) 生成当日文字策略报告
node daily-report.js

# 3) 启动实时盯盘助手（常驻）
node monitor.js           # 按 notify.config.json 的 channel 推送
node monitor.js --once    # 单次评估，打印当前策略与将触发的事件（不推送）
node monitor.js --dry-run # 常驻但只打印，不实际推送（先调试用）

# 4) 研究台账与学习器（可选）
node seed-ledger.js       # 回填历史咨询记录
node ledger.js autolog    # 全池每日模型预测自动入账（消除选择性偏差）
node ledger.js resolve    # 拉真实行情结算到期预测
node ledger.js stats      # 查看准确率（含证据分级分层 / 模型 vs 人工覆写）
node ledger.js compare    # 人工覆写 vs 模型 对照实验
node train-rl.js          # 训练 Hedge 学习器（47 标的 / 10.6 万样本，约 5 分钟）
node ablation.js          # 消融实验：扩样本是否有效 + 模型 vs 纯动量（配对显著性检验）
node ledger.js gate       # 前向检验「模型入场门槛」假设（读台账已结算快照，样本不足会明确拒绝）
curl localhost:8899/api/action   # 池级今日行动卡
node train-rl.js --topk 5 --exec-lag 1   # 组合回测参数（持仓数 / 成交滞后）
node train-rl.js --no-portfolio          # 跳过组合回测（快速训练）
```

> **实盘预测已接入学习器**：`/api/predict`、`monitor.js`、`daily-report.js` 现在都用
> **Hedge 学到的专家权重 + Platt 标定后的可信概率**，并给出是否达到**含费回测选出的交易阈值**。
> 手工模型的原始概率仍保留在 `upProbRawModel` 字段里，绝不隐藏"打折"这件事。

## 实时盯盘助手（monitor.js）

### 今日行动卡（池级合成结论）

`GET /api/action` + GUI「预测」标签页顶部，**一眼回答三个问题**：今天动不动 / 动哪只 / 下次何时看。

| 字段 | 说明 |
| --- | --- |
| `verdict` | **建仓 / 减仓 / 持有 / 观望**（合成规则写死、可审计：大盘熊市→观望或减仓；无标的通过共振+门槛→观望；有空仓且达标→建仓） |
| `checks` | 大盘（沪深300 vs MA60）/ 情绪 / 美债10Y 三道门禁 |
| `candidates` | 全池按动量排名 + 1周/1月可信概率 + 是否通过「共振 + 入场门槛」 |
| `positions` | 当前持仓的份额/成本/现价/浮动 |
| `nextReviewDate` | 按 `operatingMode` 推算的下次复查日 |
| `evidenceLevel` | **显式标注证据等级**（入场门槛为 post-hoc，未经前向验证） |

性能：冷启动约 6s，5 分钟缓存，命中约 30ms。

### 低频操作（月度为主）

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `operatingMode` | `monthly` | `monthly` / `weekly` / `daily`，决定下次复查日 |
| `signalSmoothing` | `5` | 模型概率 EMA 窗口；**`1` = 不平滑，精确复现旧行为** |

**为什么默认月度**：实测周频 topK=3 的组合换手 **5000~5900%**（≈每月 1000%）、最大回撤 **23–37%**，对 50 万本金过高。

**为什么平滑 5**：实测（测试集 w1）不平滑日动作翻转 18.3%、横截面超额 +1.519%/周（t=2.66）；
EMA5 把翻转降到 **6.8%**、超额 +1.435%（t=2.40）—— 用约 6% 的边际换 63% 的换手下降。
但过度平滑动有害：EMA20 超额掉到 +0.869%、t 降到 1.36（不再显著）。

> `operatingMode=monthly` **只降低调仓频率，不豁免止损**：触及止损/止盈时盯盘仍按 `pushPolicy=actionable` 推送。

### 「1天」周期已降级为参考

d1 方向准确率 **51.3% 低于朴素基准 51.6%**，无边际。现在 `/api/predict` 与 GUI 对 d1 输出
`decisionGrade: "reference"`，**只显示概率、不给买入/回避信号**。

### 推送策略：默认只推「可执行动作」

**背景**：原来的盯盘每 30 分钟推一次盘中快照，加上开盘策略、评分异动，一天能推十几条
—— 全是"看着有用、实际不产生任何动作"的信息噪音。现在默认**只推要动手的时刻**。

| 事件 | 默认是否推送 | 说明 |
| --- | --- | --- |
| **建仓条件触发** | ✅ 推送 | 价格 ≤ 上限 且 折溢价 ≤ 上限（含溢价危险警告） |
| **成交提醒** | ✅ 推送 | 自动轮动产生真实买卖时：明细 + 目标仓位 + 止损止盈位 |
| **轮动切换** | ✅ 推送 | 目标标的改变（该建仓 / 该减仓的信号） |
| **止损 / 止盈** | ✅ 推送 | 按**实际持仓成本**检查，跌破 / 涨破立即提醒 |
| 开盘策略 | ❌ 静默（仅写日志） | 常规播报 |
| 盘中快照 | ❌ 静默（仅写日志） | 常规播报（每 `reportIntervalMin` 分钟） |
| 评分异动 | ❌ 静默（仅写日志） | 常规播报 |
| 收盘复盘 | ❌ 静默（仅写日志） | 常规播报 |

> **静默 ≠ 不执行**：自动交易、状态机、每日台账入账照常运行，只是不再发微信打扰你。
> 被静默的事件仍会写进 `data/monitor.log`，日志里会打印
> `（静默 open、regular　pushPolicy=actionable，需要全推请用 --push=all）`。

三种模式（`notify.config.json` 里的 `pushPolicy.mode`）：

| mode | 推送范围 |
| --- | --- |
| `actionable`（**默认**） | 建仓条件 / 成交 / 轮动切换 / 止损 / 止盈 |
| `trades` | 更严格：建仓条件 / 成交 / 止损 / 止盈 |
| `all` | 旧行为，全部推送 |

命令行可临时覆盖：`node monitor.js --push=all`。
需要完全自定义时用 `pushPolicy.allowKinds: ["entry","trade","stop"]`
（给了它就以它为准，优先级高于 `mode`）。


### 推送渠道配置

编辑 `notify.config.json`（模板见 `notify.config.example.json`）：

| `channel` | 说明 | 需要填写的 `notify` 字段 |
| --- | --- | --- |
| `console` | 打印到终端（默认，免配置） | 无 |
| `serverchan` | Server酱 → 微信服务号推送（免费） | `serverchan.sendkey`（https://sct.ftqq.com 获取） |
| `pushplus` | PushPlus → 微信推送（免费） | `pushplus.token`（https://www.pushplus.plus 获取） |
| `wecom` | 企业微信群机器人 | `wecom.webhook`（群机器人 Webhook 地址） |
| `wecomapp` | 企业微信自建应用消息（可推个人微信） | `wecomapp.corpid`/`secret`/`agentid`/`touser` |
| `dingtalk` | 钉钉群机器人 | `dingtalk.webhook`（自定义机器人 Webhook 地址） |
| `generic` | 通用 HTTP 网关（可对接短信网关/自建服务） | `generic.url`（可选 `headers`/`bodyTemplate`） |

示例（微信 Server酱）：

```json
{
  "channel": "serverchan",
  "notify": { "serverchan": { "sendkey": "SCTxxxxxxxxxxxx" } }
}
```

> 短信说明：国内短信需在运营商侧开通签名与模板（付费），本项目不做直连；可用 `generic` 对接你自己的短信网关（POST `{title,text}` 到指定 URL）。

### 运行方式

**Web 服务（开机自启，推荐）**

```bash
bash start-server.sh   # 注册 launchd 开机自启并立即启动（其他人可经局域网访问）
bash stop-server.sh    # 停止并取消自启
```

- 本机访问：http://127.0.0.1:8899
- 同一 Wi-Fi 的其他人：http://<本机局域网IP>:8899（`start-server.sh` 会打印）
- 公网访问需部署到云服务器（见 `DEPLOY.md`）

**盯盘（打开网页即启动）**

1. Web 服务运行后，浏览器打开 http://127.0.0.1:8899
2. **打开网页界面即自动启动盯盘**（前端加载时调用 `/api/monitor/start`，若已在运行则复用）
3. 手动：`curl -X POST http://127.0.0.1:8899/api/monitor/start`

手动管理（可选）：

```bash
node monitor.js --once                            # 单次评估（不推送）
node monitor.js --dry-run                         # 前台调试（不推送）
nohup node monitor.js > data/monitor.log 2>&1 &   # 后台常驻（手动）
curl -X POST http://127.0.0.1:8899/api/monitor/start   # 手动启动盯盘
curl http://127.0.0.1:8899/api/monitor/status           # 查看盯盘状态
```

日志写入 `data/monitor.log`。可在 `notify.config.json` 的 `holidays` 数组里维护 A 股休市日，避免节假日误触发。
