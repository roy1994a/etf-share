## 〇、回答三个问题

### Q1：模型还有哪些不足？哪些真正影响最终目标？

| 缺陷 | 实测证据 | 影响目标 |
| --- | --- | --- |
| **D1 状态里有 5 套互相冲突的"选定策略"** | `tradingPolicy.thresholds`、`timingPolicy`（**测试集失败**：Calmar 0.208）、`rotationWeight`（w=0.25 未采纳）、`chosenStrategy`、`confluencePolicy` 并存 | 🟡 中 |
| **D2 选参准则不可靠** | 单一 Calmar 与"两半稳健"准则**都**选中了测试集 0/4 全败的择时退出族 | 🟡 中 |
| **D3 日间信号含大量噪音** | sd(p)=0.1074、sd(Δp)=0.0524、**Δp 自相关 = −0.226**；日动作翻转 18.3% | 🟠 高 |
| **D4 横截面组合换手极高** | 动量 Top-1 每日换 **26.1%**、Top-3 每日换 **78.1%**、隔 5 日 Top-3 换 **97.0%**、隔 22 日换 **100%** → 组合换手 **5000~5900%** | 🔴 **最高** |
| **D5 组合回撤过大** | w1+topK=3 最大回撤 **23–37%** | 🔴 **最高** |
| **D6 没有池级"今日行动卡"** | `/api/predict` 是单标的、GUI 绑定单一 `App.code`，看全池 13 只要逐个点开 | 🔴 **最高** |
| **D7 d1 无边际却与 m1 并列展示** | d1 方向 **51.3% < 朴素 51.6%**，但仍给"买入/回避" | 🟠 高 |
| **D8 没有"下次何时看"** | 界面无复查节奏 | 🟠 高 |
| **D9 未区分"已验证/未验证"** | 入场门槛是 post-hoc 观察，与已验证结论混排 | 🟡 中 |

> **结论：真正卡住目标的是 D4/D5/D6/D8 —— 不是"预测不够准"，而是"给出来的东西不能直接执行，且执行成本与回撤都过高"。**

### Q2：前瞻指引如何方便实盘操作？

**改造前**：给的是**单标的 × 四个周期 × 一堆概率和阈值**。用户要自己合成结论、自己逐个标的检查、自己决定仓位 —— **那是数据，不是指引。**

**改造后**：**今日行动卡**，一眼回答三个问题 —— 今天动不动 / 动哪只 / 下次何时看。

### Q3：每日都有不同，能否低频操作？

**能，而且温和平滑近似免费。** 实测（测试集 w1，同口径横截面超额）：

| 平滑窗口 | 方向命中率 | **横截面超额/周** | t 值 | 日动作翻转 | 相对原始 |
| --- | --- | --- | --- | --- | --- |
| 原始（平滑=1） | 51.98% | **+1.519%** | 2.66 | 18.3% | — |
| EMA3 | 51.79% | +1.507% | 2.53 | 9.2% | 保留 99% 超额，翻转 −50% |
| **EMA5（默认）** | 51.66% | **+1.435%** | 2.40 | **6.8%** | **保留 94% 超额，翻转 −63%** ✅ |
| EMA10 | 51.19% | +1.393% | 2.26 | 4.5% | 保留 92% 超额，翻转 −75% |
| EMA20 | 50.30% | +0.869% | **1.36** | 3.1% | ⚠️ 超额 −43%，t 掉到不显著 |

**两条结论**：
1. **EMA5~10 近似免费** —— 用 6~8% 的边际换 63~75% 的换手下降。
2. **过度平滑有害** —— EMA20 把超额打掉 43%，t 从 2.66 掉到 1.36（不再显著）。所以窗口默认 **5**，不设更大。

另外实测确认**排名本身有区分度**（第1−第3名动量差中位数 **10.92%**，第3−第5名 **2.95%**），
所以"选票"这件事有意义，问题出在**换票太频繁**，而不是选票无效。

## 一、P1：状态清理（一套策略 + 显式标注"未采纳"）

`tradingPolicy` 从"什么都往里塞"改为规范结构：

```json
"tradingPolicy": {
  "decided":   { "thresholds": {...}, "fees": {...}, "basis": "...", "confluencePolicy": {...} },
  "evaluated": {
    "timingPolicy":   { "adopted": false, "rejectReason": "测试集 Calmar 低于同周期纯动量基准（择时退出族测试集 0/4 全败）" },
    "rotationWeight": { "adopted": false, "rejectReason": "验证集与测试集结论相反，w 不可靠估计" },
    "chosenStrategy": { "adopted": false, "rejectReason": "仅为评估记录，未接入实盘" }
  },
  "operatingMode": "monthly",
  "signalSmoothing": 5
}
```

- **唯一生效来源是 `decided`**；`live-predict` 只读 `decided.thresholds` 与 `decided.confluencePolicy`（回退兼容顶层旧字段）。
- `lib/rl.js` 新增 `defaultTradingPolicy()` / `migrateTradingPolicy(tp, wholeState)`，
  **幂等**且能把散落在**顶层**的 `confluencePolicy`/`chosenStrategy` 一并收编（旧的 5 套策略就是跨两个作用域散落的）。
- GUI「研究台账」新增**「策略采纳状态」表**：策略 / 是否生效 / 验证表现 / 测试表现 / 未采纳原因。

## 三、P3：低频模式 + 信号平滑

### 配置（已写入 `notify.config.example.json` 并附说明）

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `operatingMode` | `monthly` | `monthly` / `weekly` / `daily`；决定行动卡的"下次复查日" |
| `signalSmoothing` | `5` | 模型概率的 EMA 窗口；`1` = 不平滑（**精确复现旧行为**） |

### 平滑实现

`lib/live-predict.js` 新增 `smoothedProbs()`：用同一套 `aggregate + calibrate` **回放最近 2×win 个交易日**，
取 EMA(win) 作为决策概率。同时输出 `upProbUnsmooth`，让用户看到平滑前后的差异，**不隐藏**。

**回归保证（已实测）**：`smooth=1` 时 `upProb === upProbUnsmooth`，5 个标的 × 4 周期全部相等
→ **精确复现改动前行为**。

### 平滑对 159516 的实际影响

| 平滑 | d1 | d3 | w1 | m1 |
| --- | --- | --- | --- | --- |
| smooth=1 | 47% | 45% | 30% | 52% |
| smooth=5（默认） | 49% | 47% | 29% | **56%** |

## 四、P4：把"能不能用"标清楚

### d1 降级为「参考」

d1 方向准确率 **51.3% < 朴素基准 51.6%**（无边际），但此前与 m1 并列给出买入/回避信号。

现在 `live-predict` 输出 `decisionGrade`：

| 周期 | decisionGrade | 界面表现 |
| --- | --- | --- |
| d1 | `reference` | **只显示概率**，显示"📎 参考（1天周期无边际：51.3% vs 朴素 51.6%），不用于决策" |
| d3/w1/m1 | `actionable` | 照常给 ✅买入 / ⛔回避 / ⏸观望 |

### 未验证结论显式标注

行动卡底部固定显示：

> ⚠️ 证据等级：入场门槛为 post-hoc 观察，未经前向验证（见 `node ledger.js gate`）

配合 `ledger.js gate` 的有效样本量（当前仅 1 个独立到期日）—— 卡片会明确告诉你"样本不足，仅作参考"。

## 五、怎么用（实盘操作流程）

### 正常情况：每月看一次

```bash
# 每月首个交易日前后打开
open http://127.0.0.1:8899   # → 「预测」标签页 → 今日行动卡
```

**只看行动卡的三行**：

1. **结论** —— 建仓 / 减仓 / 持有 / 观望
2. **门禁** —— 三个 ✅ 还是 ❌
3. **下次复查** —— 例如 `2026-10-01`

- 结论是 **观望** → 关掉，下个月再看（这是常态）
- 结论是 **建仓** → 候选表里绿色高亮的那几行就是标的；按行动卡给的仓位区间执行
- 结论是 **减仓** → 持仓表里浮动为负的那几行，按止损纪律处理

### 止损例外：任何时候触发都要处理

`operatingMode=monthly` **只降低调仓频率，不豁免止损**。
触及止损/止盈时盯盘仍会按 `pushPolicy=actionable` 推送（见 README 的推送策略表）。

### 想更勤一些

```json
{ "operatingMode": "weekly" }     // notify.config.json
```

但要清楚代价：**周频的换手约 5000%+、回撤 23–37%**（实测），对 50 万本金过高。

## 八、明确没做的事（以及为什么）

| 项 | 决定 | 理由 |
| --- | --- | --- |
| 把「入场门槛」接入实际买卖信号 | ❌ 仍不接入 | 它是 post-hoc 观察，验证集并未选出它。等 `ledger.js gate` 攒够 ≥10 个独立到期日 |
